# Changelog 规范

## 模板

```markdown
## <branch-name>

================================================================================

**spec:** `path/to/plan.md`

**todo**（有待办时才写，全部完成后删除整块）
- [ ] 描述性名称

**feat: commit message（与 todo 同级）**
1. ✅ 描述性名称 · 🧪
2. ✅ 描述性名称

**feat: 第二次 commit（编号在同一 spec 内续接）**
3. ✅ 描述性名称

================================================================================

**chore: 非 spec commit 标题**
1. ✅ 描述性名称
```

符号说明：条目末尾加 ` · 🧪` 表示有测试覆盖，无标记表示无测试（配置/文档/chore 类）

---

## 规则

**文件**
- 每天一个文件：`changelogs/YYYY-MM-DD.md`，文件头一行写 `# YYYY-MM-DD`
- 每个分支一个 `## branch` 块，块内含多个 spec 组或非 spec 组

**spec 组**
- 以 `================================================================================`（40 个 `=`）开头
- 包含 `**spec:**` 路径（必填）、`**todo**`（有待办时才写）、一到多个 `**commit message**` + 条目
- `**todo**` 和 commit 标题平级，都是 spec 块的子项
- 同一 spec 内编号续接；todo 全部完成后删除整个 todo 块
- 同一分支块内多个 spec 组**按时间倒序排列**，新 spec 追加到最顶部（紧跟 `## branch` 行之后），旧的在下面

**非 spec 组**
- 以 `================================================================================` 开头
- 无 spec 字段，直接用 `**commit message**` + done 列表

**块分隔符**
- 每个 spec 组和非 spec 组之间用 `================================================================================`（40 个 `=`）分隔

**时机**
- 写完计划文档后：在分支块**顶部**（紧跟 `## branch` 行之后）追加 `================================================================================` + 新 spec 组；若无分支块则先创建
- 代码实现完成后：删除对应 todo 条目（todo 清空则删整块），追加 done 条目
- commit 时：在 spec 组内追加 `**commit message**` 行（若该组尚无 commit 标题），done 条目续接其后
- 非 spec commit（chore/fix/docs）：在分支块末尾追加 `================================================================================` + `**commit message**` + done 列表

**读取**
- 不需要扫所有 changelog，只读最新一篇

## 会话开始 / 任务前流程（分级触发）

### L0 — 每次会话开始必做（轻量，零成本）

1. 执行 `git branch --show-current`
2. 执行 `git status`（仅看是否有未提交改动，不阻塞）

这两步无需读 changelog，目的是让 Claude 知道当前分支和工作区状态。

### L1 — 用户意图涉及实施/继续开发/commit/部署时

触发条件（语义判断，非关键词匹配）：
- 用户要求实现功能、修 bug、改代码
- 用户要求 commit、push、部署
- 用户说「继续」「接着做」

执行：
1. 读取 `changelogs/` 下**日期最新**的 `.md` 文件，了解当前进展
2. 若 changelog 记录的活跃分支与当前分支不一致，提醒用户

### L2 — 用户说「todo」「下一步」或明确提出新功能/新模块时

触发条件：
- 用户说「todo」「下一步」「还有什么要做」
- 用户提出**全新**的功能/模块/Phase（非延续当前分支工作）

执行（L1 基础上追加）：
1. 读取最新 changelog 中对应分支块的未完成 todo
2. 若存在未完成 todo → 列出待办，询问：「当前还有未完成的 TODO，是先处理 TODO，还是开始新任务？」；**在用户明确回答前，禁止开始执行新任务**
3. 若 todo 为空 → 主动读取 `docs/superpowers/plans/` 下最新的计划文件，提议下一步；若无计划文件则询问用户意图
