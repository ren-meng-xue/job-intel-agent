# Changelog 规范

## 模板

```markdown
## <branch-name>

================================================================================

**spec:** `path/to/plan.md`

**todo**（有待办时才写，全部完成后删除整块）
- [ ] 描述性名称

**feat: commit message（与 todo 同级）**
1. ✅ 描述性名称 · 🧪
2. ✅ 描述性名称

**feat: 第二次 commit（编号在同一 spec 内续接）**
3. ✅ 描述性名称

================================================================================

**chore: 非 spec commit 标题**
1. ✅ 描述性名称
```

符号说明：条目末尾加 ` · 🧪` 表示有测试覆盖，无标记表示无测试（配置/文档/chore 类）

---

## 规则

**文件**
- 每天一个文件：`changelogs/YYYY-MM-DD.md`，文件头一行写 `# YYYY-MM-DD`
- 每个分支一个 `## branch` 块，块内含多个 spec 组或非 spec 组

**spec 组**
- 以 `================================================================================`（40 个 `=`）开头
- 包含 `**spec:**` 路径（必填）、`**todo**`（有待办时才写）、一到多个 `**commit message**` + 条目
- `**todo**` 和 commit 标题平级，都是 spec 块的子项
- 同一 spec 内编号续接；todo 全部完成后删除整个 todo 块
- 同一分支块内多个 spec 组**按时间倒序排列**，新 spec 追加到最顶部（紧跟 `## branch` 行之后），旧的在下面

**非 spec 组**
- 以 `================================================================================` 开头
- 无 spec 字段，直接用 `**commit message**` + done 列表

**块分隔符**
- 每个 spec 组和非 spec 组之间用 `================================================================================`（40 个 `=`）分隔

**时机**
- 写完计划文档后：在分支块**顶部**（紧跟 `## branch` 行之后）追加 `================================================================================` + 新 spec 组；若无分支块则先创建
- 每次 commit 前：删除已完成的 todo 条目（todo 清空则删整块），在 spec 组末尾追加 `**commit message**` + done 条目
- 非 spec commit（chore/fix/docs）：在分支块末尾追加 `================================================================================` + `**commit message**` + done 列表

**读取**
- 不需要扫所有 changelog，只读最新一篇

## 会话开始 /「todo」流程

每次会话开始时，以及用户说「todo」或询问下一步时，按顺序执行：

1. 读取 `changelogs/` 下**日期第二新**的 `.md` 文件（即倒数第二篇）：
   - 若存在未完成的 todo → 提醒用户「上一个 changelog（YYYY-MM-DD）还有未完成项，是否先处理？」，列出待办，等待用户决定
   - 若没有 todo → 继续下一步
2. 读取 `changelogs/` 下**日期最新**的 `.md` 文件，了解当前进展
3. 执行 `git branch --show-current`，若与 changelog 记录分支不一致，提醒用户切换
4. 若 changelog 有未完成的 todo → 列出待办，询问从哪条开始
5. 若 changelog todo 为空 → 主动读取 `docs/superpowers/plans/` 下最新的计划文件，提议下一步任务；若无计划文件则询问用户意图
