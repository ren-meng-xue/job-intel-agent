# Skill：前端视觉设计（frontend-design）

## 触发条件
用户主动要求生成**独立 HTML 页面、视觉作品、海报、落地页、Web 组件**时读取本文件。
产物为**自包含的单个 HTML 文件**，可直接在浏览器打开，无需任何构建工具或服务器。

---

本技能用于指导创建具有独特视觉语言的生产级前端界面，避免生成泛化、廉价、"AI 味"浓重的设计风格。实现真正可运行的代码，并对美学细节与创意表达投入极高关注。

用户会提供前端需求：一个组件、页面、应用程序或界面。用户也可能提供其用途、目标受众或技术限制等背景信息。

## 设计思维（Design Thinking）

在开始编码之前，先理解上下文，并明确一个大胆且清晰的审美方向：

- **目的（Purpose）**：这个界面解决什么问题？谁会使用它？
- **风格语气（Tone）**：选择一种极致风格：
  - 极简主义（brutally minimal）
  - 极繁混乱（maximalist chaos）
  - 复古未来主义（retro-futuristic）
  - 自然有机（organic/natural）
  - 奢华精致（luxury/refined）
  - 玩具感/趣味感（playful/toy-like）
  - 杂志编辑风（editorial/magazine）
  - 粗野主义（brutalist/raw）
  - 装饰艺术几何风（art deco/geometric）
  - 柔和粉彩（soft/pastel）
  - 工业实用主义（industrial/utilitarian）
  - 等等……

可以从这些方向获得灵感，但最终设计必须真正忠于你所选择的美学方向。

- **限制条件（Constraints）**：
  技术要求（框架、性能、无障碍等）。

- **差异化（Differentiation）**：
  什么会让这个设计令人难忘？
  用户最终会记住什么？

### 关键原则（CRITICAL）

必须选择一个明确的概念方向，并精准执行。

无论是大胆极繁，还是克制极简，都可以成立——关键在于"有意识的设计"，而不是单纯堆叠视觉强度。

随后实现真正可运行的代码（HTML/CSS/JS），并满足以下要求：

- 达到生产级标准
- 视觉上惊艳且令人难忘
- 拥有统一一致的审美视角
- 每一个细节都经过精细打磨

---

# 前端美学指南（Frontend Aesthetics Guidelines）

重点关注：

## Typography（字体排版）

选择美观、独特、有个性的字体。

避免使用过于泛滥的字体，例如：

- Arial
- Inter

优先选择真正具有设计气质的字体组合：

- 一个有表现力的展示字体（display font）
- 一个精致克制的正文字体（body font）

让字体本身提升整体界面的审美层次。

---

## Color & Theme（配色与主题）

坚持统一且完整的视觉语言。

- 使用 CSS Variables 保持一致性
- 强主色 + 锐利强调色
  往往优于保守、平均分布的色板

不要害怕鲜明的主导色彩。

---

## Motion（动态与动画）

利用动画创造氛围与微交互。

- 优先使用纯 CSS 动画

重点应该放在：

- 高冲击力的关键时刻
- 精心编排的页面加载动画
- staggered reveal（交错渐显）
- animation-delay 的节奏控制

相比于到处都是微交互：

一个真正精致的入场动画，
往往更能带来愉悦感。

同时加入：

- 滚动触发动画
- 意料之外的 hover 状态
- 有惊喜感的反馈效果

---

## Spatial Composition（空间构成）

避免平庸布局。

尝试：

- 非对称结构
- 元素重叠
- 对角线视觉流动
- 打破网格系统
- 大面积留白
- 或高密度但有秩序的排版

布局应该拥有"设计意图"，而不是仅仅"排列元素"。

---

## Backgrounds & Visual Details（背景与视觉细节）

创造氛围感与空间深度，
而不是默认纯色背景。

可以使用：

- Gradient Mesh（渐变网格）
- Noise Texture（噪点纹理）
- 几何图案
- 半透明层叠
- 强烈阴影
- 装饰性边框
- 自定义光标
- 胶片颗粒感（grain overlay）

这些视觉细节必须与整体审美保持一致。

---

# 严禁出现的 AI 风格问题

绝对不要使用：

- 泛滥字体（Inter、Roboto、Arial、系统字体）
- 陈词滥调配色
  （尤其是"白底紫渐变"）
- 可预测的布局
- 模板化组件结构
- 缺乏上下文个性的 Cookie-cutter 设计

---

# 创造性原则

要主动进行创造性解读，
做出真正"像设计师设计出来"的选择。

每一次设计都应该不同：

- 不同主题
- 不同字体
- 不同美学体系
- 不同视觉结构

绝不要反复收敛到相同风格。

---

# 输出规范

- 产物：**单个自包含 HTML 文件**（内联 CSS + JS，无外部依赖，可直接浏览器打开）
- 保存路径：由用户指定，或默认输出到对话中展示
- 不生成 React 组件 / Next.js 页面（那是 `frontend.md` 的职责）
