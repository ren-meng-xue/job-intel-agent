# 任务状态追踪与开发闭环设计

## 背景

原有 `feature-dev.md` 的 Step 0-8 只存在于对话 context 中，换人或重开会话后任务状态丢失，接手者无法得知当前进度。本次设计目标：在不引入新工具的前提下，建立一套完整的、跨会话可恢复的开发闭环。

---

## 核心决策

### 状态文件放在哪里
Spec 文件是设计文档，保持稳定不追踪状态。任务状态单独存放于 `.claude/tasks/`，与 spec 同名关联，不依赖 spec 存在。

### 命名绑定规则
```
spec：docs/superpowers/specs/YYYY-MM-DD-<feature>-design.md
task：.claude/tasks/YYYY-MM-DD-<feature>.md
```
`<feature>` 完全一致，task 文件第一行写入 spec 路径，无 spec 时写 `spec: none`。

### Gate 设计原则
子任务执行阶段 Claude 全程自动打 ✅，不打断用户。测试和代码审查合并为一个验证阶段自动执行。Gate 是唯一决策点，出现时附带 Changelog 内容，用户看到全貌后再决策。

### 阶段门控选项
```
「1」commit + push
「2」仅 commit，稍后 push
「3」继续修改
```
选「2」后 task 文件保留状态，下次会话扫描恢复。选「3」后用户说「好了」重回验证。

---

## 入口设计

| 入口 | 触发场景 | 关键差异 |
|---|---|---|
| 业务不确定 | 需求模糊 | brainstorming → 完整 spec |
| 业务已确定 | 需求清晰 | 精简 spec（5分钟） |
| Bug 修复 | 发现缺陷 | 不强制全量测试，先 MRE |
| 重构 | 结构改善 | 先检查覆盖率，回归测试保护 |
| Hotfix | 线上紧急 | 用户提供目标分支，只跑关键路径 |

---

## 会话恢复机制

每次会话开始，Claude 扫描 `.claude/tasks/` 中 Gate 未全部 ✅ 的文件，主动提示用户继续或忽略。task 文件是接手者的第一信息来源。

---

## 放弃路径处理

- Bug 修复无法复现：先要 MRE，仍无法复现才列原因存档
- 重构失败放弃：保留回归测试单独 commit，只还原结构改动
- 无法建立回归测试：停止重构，告知原因
